# UI 方向调查、线框与裁决

本文件记录三个独立设计方向。三者都基于当前代码和真实安装态审计，不是同一布局的换色版本。

## 1. 共同问题定义

当前一个 WebviewView 同时容纳题库、教练、画像、配置、复盘和内测信息。它在 320–360px 可以工作，但：

- 260px 时导航截断，统计项换行造成布局跳动；
- 所有动作同权，当前下一步不突出；
- 设置、连接状态、画像统计和内部控制长期裸露，主界面更像工程配置面板而不是学习产品；
- 600px 时扩宽侧栏会伤害代码编辑器；
- AI 响应覆盖单一结果区，不是可恢复时间线；
- Webview 与 Host 各自保存 thread；
- 协议没有 request correlation；
- 只有单个 360px media query，没有 reduced-motion；
- 主要 UI 测试是源码字符串断言。

## 2. 方向 A：原生导航、单会话教练、宽屏证据复盘

### 2.1 设计签名

```text
TreeView 题库/历史
        ↓ 选择 Attempt
WebviewView 当前会话 ↔ 代码编辑器
        ↓ 完成/放弃
Webview Panel 复盘/画像/推荐证据
```

### 2.2 线框

```text
┌─ Primary Sidebar ─────────────┐  ┌─ Editor Group ───────────────────┐
│ 题库与历史            [＋][↻] │  │ P1001.py | 学习复盘              │
│ ▾ 进行中                      │  │                                  │
│   ● P1001 A+B     编码中      │  │          学生代码编辑器           │
│ ▸ 待练 12                     │  │                                  │
│ ▸ 历史 38                     │  ├──────────────────────────────────┤
├─ 当前会话 ────────────────────┤  │ 摘要｜证据｜画像｜推荐            │
│ P1001 · 编码中 · P1001.py     │  │ 痛点时间线 / 评分依据 / 纠偏      │
│ 教练：先检查输出格式……        │  │ [这条不准] [回滚] [练下一题]      │
│ [追问____________________][↑] │  └──────────────────────────────────┘
│ [给提示] [运行样例] [更多…]   │
└───────────────────────────────┘
```

### 2.3 优点

- TreeView、Settings、QuickPick、Output、Diagnostics 等回归 VS Code 原生能力。
- 题目集合导航、当前会话和深层复盘职责清晰。
- 侧栏保持窄而稳定，600px 的复杂内容进入编辑器 Panel。
- 原生 TreeView 自带键盘、选中、折叠和主题行为。

### 2.4 隐藏成本

- 三个表面必须共享一个 `SessionCoordinator`，否则会变成三份状态。
- Panel serializer、Tree selection、Webview View 恢复和跨表面焦点需要真实 Extension Host 测试。
- 如果 TreeItem 被当按钮或塞进过多信息，原生优势会消失。

## 3. 方向 B：单一自适应 React 工作台“Attempt Spine”

### 3.1 设计签名

一题一会话、一条证据轨道、一个明确下一步。题库与画像证据可按需进入 Inspector；设置仍回归 VS Code 原生 Settings/命令入口。React 组件树在 260–600px 通过容器查询自适应。

### 3.2 线框

```text
260 / 320 / 360px
┌────────────────────────────┐
│ P5730  编码中       ● 在线 ⋯│
│ [题] [码] [教] [检] [判]    │
├────────────────────────────┤
│ 10:21  你：边界为什么错？    │
│ ▎教练输出中…                 │
│   数组最后一个下标是 n-1…    │
│ ┌ 检查点 ─────────────────┐ │
│ │ n=1 时循环执行几次？      │ │
│ │ [回答_______________][↑] │ │
│ └─────────────────────────┘ │
├────────────────────────────┤
│ [提示]       [运行]   [提交] │
│ [继续问________________][↑] │
└────────────────────────────┘
```

```text
600px
┌ P5730 · main.cpp · 检查点 2/3 · ● 在线 ┐
├───────────────┬─────────────────────────┤
│ 当前会话       │ 解题证据轨道            │
│ 文件 / 语言    │ 你 → 教练 → 检查点      │
│ 样例状态       │ → 运行 → 判题 → 复盘    │
│ 待练队列       │                         │
│ 画像线索       │                         │
├───────────────┴─────────────────────────┤
│ [主动作] [次动作]  继续提问 [________][↑]│
└─────────────────────────────────────────┘
```

### 3.3 优点

- 流式时间线、状态 reducer、局部更新和组件行为测试最自然。
- 一个 bundle 和协议可在 WebviewView/Panel host 间复用。
- 宽度变化不替换组件树，可保留流式内容和焦点。

### 3.4 隐藏成本

- WebviewView 不能直接成为编辑器 tab；要进入中心编辑器仍需薄 WebviewPanel host。
- 容易在 React 中重新造题库、设置、通知和列表行为。
- 如果先 React 化、后建状态机，只会把隐式竞态搬进 JSX。

## 4. 方向 C：ONE NOW / NEXT / BEFORE 时间线与行动队列

### 4.1 设计签名

```text
一个置顶行动 + 一个折叠后续队列 + 一条只追加学习时间线
NowAction = derive(project(replay(events)), capabilities, connectivity)
```

它取消“AI 教练 / 题目 / 学习画像”三个平级首页。主视图只回答：现在做什么、为什么、之前发生了什么。

### 4.2 线框

```text
260–360px
┌──────────────────────────┐
│ P1030 · active       [≡] │
│ 本地可用 · AI 在线        │
├─ 现在 ───────────────────┤
│ 运行 2 个样例             │
│ 因为代码已改变，尚未验证  │
│ [      运行样例      ]    │
├─ 接下来 2 项 ──────── [>]│
├─ 学习时间线 ──────────────┤
│ ● 10:21 保存代码   已完成 │
│ │  绑定快照 a81f…         │
│ ● 10:18 教练提示   已完成 │
│ │  “先检查子树边界”  [>]  │
│ ● 10:16 开始编码          │
└──────────────────────────┘
```

```text
600px
┌────────────────────────────────────────────┐
│ P1030 · 求先序排列     队列[3]  题目  更多 │
├─ 现在：确认发起正式提交 ───────────────────┤
│ AtCoder abc086_a · Python · hash a81f…      │
│ [              查看并确认                ]│
├─ 接下来 ───────────┬─ 学习时间线 ─────────┤
│ 复盘               │ 10:31 本地样例 2/2   │
│ 推荐迁移题         │ 10:28 检查点通过     │
└────────────────────┴───────────────────────┘
```

### 4.3 优点

- 与事件事实源和可恢复会话天然一致。
- 窄侧栏里只有一个主行动，认知负担最低。
- 错误、取消、离线和迟到响应都可作为事件保留，不覆盖历史。

### 4.4 隐藏成本

- 时间线若不是领域投影，只会变成更长的卡片列表。
- 批量题库管理不适合塞进主时间线，仍需独立集合视图。
- `NextActionPolicy` 必须在 Host/domain，不可由 Webview 临时推断。

## 5. 评分矩阵

分数 1–5；加权总分满分 5。

| 维度 | 权重 | A 混合壳 | B 单 React | C 行动时间线 |
| --- | ---: | ---: | ---: | ---: |
| 符合 VS Code 原生 UX | 0.18 | 5 | 2 | 3 |
| 260px 可用性 | 0.16 | 5 | 4 | 5 |
| 流式/状态表现力 | 0.14 | 4 | 5 | 5 |
| 深层复盘可读性 | 0.10 | 5 | 4 | 3 |
| 迁移风险 | 0.12 | 4 | 3 | 4 |
| 可测试性 | 0.12 | 5 | 5 | 5 |
| 集合导航效率 | 0.08 | 5 | 3 | 2 |

## 6. 最终裁决：A 的壳 + C 的会话模型 + B 的组件实现

目标 UI 不是三选一，而是明确的层级组合：

1. **壳层采用 A**：原生 `ProblemLibraryTreeProvider` 管题库/历史；`CurrentSessionViewProvider` 管当前会话；`LearningReviewPanel` 管复盘、画像证据和策略解释。
2. **会话交互采用 C**：当前 WebviewView 遵循 `ONE NOW / NEXT / BEFORE`，一个主行动、一个后续队列、一条事件时间线。
3. **Webview 实现采用 B 的技术**：React + Vite + 纯 reducer + 容器查询；View 和 Panel 复用协议、tokens 与组件，不复用领域状态。
4. **配置与诊断采用原生渐进披露**：View 标题栏只保留齿轮/账号/诊断图标；设置打开 `@ext:kaiserunix.student-autocomplete-lab`，平台账号使用 Command Palette/QuickPick，诊断进入 Output 或按需 Panel。正常学习时不展示 provider id、模型参数、feature flags、遥测或连接配置。

不采用：

- 继续扩建当前三 Tab 模板字符串；
- 单一巨型 React Webview 替代所有 VS Code 原生表面；
- 纯时间线替代题库集合导航；
- 通过 `retainContextWhenHidden` 掩盖状态恢复缺失；
- 让 Webview 自己决定下一教学动作或提交能力；
- 把账号、模型、MCP、策略开关和调试状态做成长期可见的设置卡片。

## 7. 产品级视觉与披露层级

这次重置不是把旧控件搬进 React。首屏视觉顺序固定为：题目与阶段、当前行动、当前反馈、学习时间线；任何设置、内部统计和技术诊断都不能抢在这四层之前。

### 7.1 主工作面

- 一个主行动必须在尺寸、位置和对比度上明显高于次动作；次动作进入短工具栏或菜单。
- 使用连续 band、细分隔线和留白建立层级，不用卡片套卡片，也不把每个状态做成独立框。
- 标题、阶段和反馈采用紧凑工作台字号；不使用营销式大标题、装饰渐变、发光块或无意义循环动画。
- 正常态只显示用户语言，例如“本地样例可用”；provider id、schema、hash、模型、token 和 feature flag 只在详情/诊断中出现。
- 题面摘要、教练动作、运行结果和推荐理由各有稳定视觉语法，不能全部退化成同样的文本框。
- 动态感来自状态转场、局部进度、验证完成和时间线追加；布局骨架在流式期间保持稳定。

### 7.2 配置与诊断

| 内容 | 默认入口 | 主界面可见范围 |
| --- | --- | --- |
| 扩展设置 | View 标题栏齿轮、Command Palette、VS Code Settings | 不显示设置表单；只在设置导致动作不可用时给一句原因 |
| 平台账号/凭据 | `管理平台账号` 命令 + QuickPick/native auth | 仅显示脱敏账号名和需要登录的行动提示 |
| MCP/provider 管理 | `管理 OJ 提供方` 命令 | 正常态最多一个聚合健康图标；异常时展开受影响能力 |
| 模型与预算 | VS Code Settings | 只显示当前动作是否可用，不显示 endpoint/key/temperature |
| 策略/实验开关 | 内部受控设置或开发命令 | 朋友版主界面完全隐藏 |
| 日志与诊断 | Output、Diagnostics、按需详情 Panel | 错误态提供“查看诊断”；不常驻技术文本 |

### 7.3 视觉评审硬门

- 260/320/360/600px 截图中，首屏不出现设置表单、feature flag、provider 配置、模型参数或内部统计表。
- 盲看截图时，评审者应能在 5 秒内指出“当前题、当前阶段、下一步”；若首先注意到设置或状态卡数量，则失败。
- 同一视口内常驻主按钮最多 1 个、直接可见次动作最多 2 个；其余进入菜单或按需详情。
- UI fixture 必须包含“正常连接”和“多 provider 异常”两种状态，证明正常态克制、异常态可诊断。
- 截图评审单独记录层级、密度、一致性、主题适配和内部信息泄露，不以“无溢出”替代视觉质量判断。

## 8. 目标响应式规则

| 宽度 | Tree/会话 View | 当前行动 | 时间线 | 次要能力 |
| ---: | --- | --- | --- | --- |
| 260px | 单列，6px 外边距 | 全宽按钮，44px 高 | 元数据压成一行，正文最多 3 行后展开 | 全进菜单/抽屉 |
| 320px | 单列，8px 外边距 | 图标 + 短标签 | 检查点/运行纵排 | 允许 2 个次动作 |
| 360px | 单列增强 | 一个主动作 + 2 次动作 | 状态元数据可两列 | 题面/队列抽屉 |
| 600px | 会话可双列，但侧栏不建议长期保持 | 主动作仍唯一 | `Next` 与 timeline 双列 | 深层复盘转 Panel |

稳定性约束：

- 使用 `container-type: inline-size`，不按 window viewport 猜宽度。
- 固定操作栏与状态标记尺寸；流式文本、badge 和 hover 不得改变布局宽度。
- 页面更新不得重建根节点；草稿、输入、焦点和滚动锚点保持。
- 题名、平台错误和超长英文 token 使用换行/截断 + 可访问全称，不产生水平滚动。

## 9. 状态到 UI 规范

| 状态 | 唯一主行动 | 局部动态 | 恢复动作 |
| --- | --- | --- | --- |
| `empty` | 导入题目 / 恢复会话 | 最近会话骨架 | 重新加载本地索引 |
| `preparing` | 取消准备 | readiness 分阶段进度 | 重试失败步骤 |
| `coding` | 运行样例或请求一级提示，由策略投影决定 | 文件/hash 变更提示 | 重新绑定文件 |
| `coaching.streaming` | 停止生成 | 句/块级 delta，不逐 token 重排 | 从已完成 turn 重试 |
| `checkpoint` | 提交回答 | 输入草稿、验证状态 | 仍不懂/跳过并记录 |
| `running` | 停止运行 | 编译/样例进度 | 重跑失败样例 |
| `submit.confirming` | 查看并确认 | 无自动倒计时提交 | 代码变化则废弃 intent |
| `judging` | 取消轮询/返回编码 | 官方 job 进度 | outcome unknown 只查询 |
| `reviewing` | 确认复盘 | 证据、纠偏和 patch 差异 | 拒绝/修正证据 |
| `recommending` | 开始所选题 | 排序理由加载 | 使用 deterministic fallback |
| `offline` | 继续本地编码/运行 | capability banner | 网络恢复后重新确认远程动作 |
| `recovering` | 从稳定检查点重试 | 可复制诊断 | 返回编码或打开 Output |

## 10. 动效与可访问性

- 动效只用于状态变化：120–180ms opacity/transform；不使用装饰性循环动画。
- 同时支持 `@media (prefers-reduced-motion: reduce)` 与 VS Code Webview reduced-motion class。
- reduced-motion 下取消平滑滚动、脉冲、旋转和闪烁光标，使用静态“正在生成/运行”文本。
- 流式区域 `aria-live="polite"` 按句节流，不逐 token 朗读，不抢焦点。
- `Esc` 先关闭抽屉，再取消当前 operation；提交确认不可由 `Ctrl+Enter` 直接越过预览。
- 抽屉关闭后恢复触发按钮；状态切换移除当前控件时回到 `NowAction`；返回代码时恢复编辑器。
- `vscode.setState` 只保存草稿、Inspector、focus key、scroll event anchor 和 attemptId；领域状态由 Host 恢复。

## 11. UI 证据门

固定矩阵：`260/320/360/600 × zh/en × light/dark/high-contrast × normal/reduced-motion`。

每个矩阵至少验证：

- `documentElement.scrollWidth <= clientWidth`；
- 可见控件 bounding box 不重叠、不越界；
- 主行动两次操作内可达；
- 请求中输入草稿不丢；
- 刷新/隐藏/重开恢复同一 attempt；
- 迟到 delta 不写入新会话；
- 全键盘完成导题、提示、检查点、运行、提交预览取消、复盘和推荐；
- 焦点返回有确定断言；
- 截图差异经人工审核，不只比较像素阈值；
- 真实 Extension Host 安装态通过，不能只跑浏览器组件测试。
